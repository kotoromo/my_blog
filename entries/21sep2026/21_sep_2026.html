So from the Odin Project I left off at the Box Model. This whole lecture is about positioning and layout.

All elements are bounded by a box. And all elements are organized within boxes too. There are different ways in which the size of a box containing an element can be resized. There is padding, border and margin.

So basically, padding separates the content from the boundary of the bounding box. Then there's border which defines the actual width of the boundary, and finally there is margin which defines the space separating the whole box (so the padding + border) from the rest of the boxes.

According to the mdn documentation for the box model, there are two types of boxes: block and inline. Their names are due to how they behave in terms of page flow and the relation to other boxes on the page. Furthermore, boxes have different display types. There is an inner and an outer display type.

The block box type seems pretty rigid. It fill outs the inline space it ocupies, so if width is not specified, then the box will fill out all of the width. Otherwise, it preserves its configured height and width. It also pushes out other boxes according to the padding, margin and border. A box block also breaks onto a new line, which I think it means that it occupies the whole line.

Now, as for boxes of type inline, the box won't break onto a new line, the width and height have no effect, the top and botom padding will change the size of the box without affecting the position of surronding content which can cause overlapping, and the left and right padding will affect the positioning of surrounding inline content.

Now, If I'm being completely honest, I did not really get how inline box types behave.

The block and inline display values are outer display types, because they affect how the box is laid out in relation to other boxes around it. However, the iner display types affect how the elements inside the box are laid out.
